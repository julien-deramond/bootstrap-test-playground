Issue pg-160: late Bootstrap never starts the load-time data APIs

Steps to reproduce

  1. Open this page. Its script waits for window.load plus 100 ms, then calls import('bootstrap'), as a lazily loaded chunk or a late-hydrated island would. The playground's shared main.js isn't loaded, because it replays DOMContentLoaded and load after its own dynamic import.
  2. Check whether the autoplaying carousel and the scrollspy have an instance (getInstance()) without any getOrCreateInstance() call. The chip input and the range are controls: their data APIs run once the document is parsed, so they must have one.

Expected

Every component has an instance as soon as Bootstrap has loaded, whenever that is: the carousel slides by itself and the scrollspy marks the link of the visible heading.

Actual

The carousel and the scrollspy stay inert, with no instance, until something calls getOrCreateInstance() on them. They wait for a load event on window that has already fired.
