# Bootstrap test playground

A Vite multi-page playground for Bootstrap v6 (`twbs/bootstrap`, branch `v6-dev`). See [README.md](README.md) for how it works.

## Conventions

- Use **v6 markup** (for example `btn-solid theme-primary`, `.menu`, native `<dialog>`). When unsure, check the docs examples in `kitchen-sink/` or the v6 docs source, not v5 habits. Some v5 classes are gone, such as `.lead`.
- Bootstrap is compiled from source: Sass from `scss/` and JS from `js/src/index.ts`. `postcss.config.js` mirrors Bootstrap's build, which adds the `--bs-` prefix.
- `kitchen-sink/*.html` is generated by `npm run sync-kitchen-sink`. Never edit it by hand.
- `configs/default/` holds Bootstrap's defaults and stays pristine. Save experiments with `npm run save-config <name>`.
- New pages get a `<meta name="description">` and `<meta name="playground-tags">` (reuse existing tags) so search on the home page and the <kbd>Ctrl</kbd>+<kbd>K</kbd> switcher can find them. See "Finding pages" in the README.
- Reproductions go in `issues/<name>/` (`npm run new-issue <name> -- --config <config>`). Name them after the upstream issue number when one exists, or `pg-<number>` after the issue in this repository.

## Upstream issue tracking

Whenever you find a potential bug in Bootstrap itself (not in this playground), record it as an issue in **this repository** (`julien-deramond/bootstrap-test-playground`), then keep its label in sync with what happens upstream. Never open issues or PRs on `twbs/bootstrap`, and never comment there, unless the user explicitly asks.

### Labels

Each tracking issue carries exactly one of these labels. Swap them; never stack them.

| Label | Meaning |
| --- | --- |
| `upstream` | Potential Bootstrap bug, not reported upstream yet |
| `upstream-reported` | An upstream issue or PR exists for it |
| `upstream-fixed` | Fixed upstream. The tracking issue is then closed |

Create them if they're missing:

```sh
gh label create upstream --color FBCA04 --description "Potential Bootstrap bug, not reported upstream yet" --force
gh label create upstream-reported --color 1D76DB --description "Reported upstream (twbs/bootstrap issue or PR exists)" --force
gh label create upstream-fixed --color 0E8A16 --description "Fixed upstream" --force
```

### 1. Record a potential bug (`upstream`)

1. Look for duplicates in this repository (open and closed) and upstream:
   ```sh
   gh issue list --label upstream,upstream-reported,upstream-fixed --state all --search "<keywords>"
   gh search issues --repo twbs/bootstrap "<keywords>"
   gh search prs --repo twbs/bootstrap "<keywords>"
   ```
   If upstream already has an issue or PR, skip to step 2 and label it `upstream-reported` right away.
2. Create the issue with the `upstream` label. The title describes the bug in Bootstrap's terms. The body includes:
   - **Summary**: one or two sentences
   - **Bootstrap version**: the `v6-dev` commit (from `package-lock.json`, or `git rev-parse HEAD` in a local checkout)
   - **Reproduction**: steps, and the `issues/pg-<number>/` page once it exists
   - **Expected / Actual**
   - **Root cause**: `file:line` in `twbs/bootstrap` with a permalink, when known
   - **Possible fix**: when known
3. When a reproduction page helps, create it with `npm run new-issue pg-<number>` and link it from the issue.

### 2. Reported upstream (`upstream-reported`)

When an upstream issue or PR exists, whoever opened it:

```sh
gh issue edit <n> --remove-label upstream --add-label upstream-reported
gh issue comment <n> --body "Reported upstream: twbs/bootstrap#<upstream-number>"
```

Also put the upstream link in the reproduction page, if there is one.

### 3. Fixed upstream (`upstream-fixed`, then close)

When the upstream fix lands on `v6-dev`, meaning the PR is merged or the issue is closed as completed:

1. Check the fix in the playground when practical (`npm run update-bootstrap`, then the reproduction page).
2. Update and close:
   ```sh
   gh issue edit <n> --remove-label upstream-reported --add-label upstream-fixed
   gh issue close <n> --reason completed --comment "Fixed upstream in twbs/bootstrap#<pr> (<commit>)"
   ```

### Status sweep

Run a sweep when starting work that touches upstream behavior, after `npm run update-bootstrap`, or when the user asks:

```sh
gh issue list --label upstream --state open          # anything reported upstream since? → step 2
gh issue list --label upstream-reported --state open # fixed yet? → step 3
```

For each `upstream-reported` issue, check the linked upstream issue or PR (`gh issue view <n> --repo twbs/bootstrap`, `gh pr view <n> --repo twbs/bootstrap --json state,mergedAt,mergeCommit`).
